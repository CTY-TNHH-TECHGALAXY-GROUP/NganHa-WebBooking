# Webbooking CMS and SEO Hardening Plan

## Status

Source implementation is in progress. The additive Supabase migration is available
at `supabase/migrations/20260906_webbooking_cms_foundation.sql` and must be applied
before deploying these access-controlled CMS routes.

## Scope

This admin is a CMS and SEO console for the public website:

- Homepage, footer, history, service media, hero video, flipbook, SEO, blog, and Lost & Found.
- Public content must keep rendering after admin access is locked.
- Booking checkout, cart, booking email, and the public `/api/bookings` flow are out of scope.
- Do not build or maintain an admin booking dashboard in this workstream.

## Compatibility Rules

1. Never rename, drop, or change the type of a live table or column.
2. New database tables use the `Webbooking` prefix and PascalCase names.
3. Additive SQL uses `IF NOT EXISTS` where PostgreSQL supports it.
4. New source reads new fields first and falls back to existing data during migration.
5. Existing tables remain the source of truth until the replacement has passed production smoke tests.
6. Every migration must be applied first to a Supabase staging project or database branch.

## New Tables

### 1. `WebbookingAdminUsers`

Purpose: server-verified authorization for CMS and SEO administration.

| Column | Type | Notes |
| --- | --- | --- |
| `user_id` | `uuid` primary key | FK to `auth.users(id)` |
| `role` | `text` | `owner`, `editor`, or `reception` |
| `is_active` | `boolean` | defaults to `true` |
| `created_at` | `timestamptz` | defaults to `now()` |
| `updated_at` | `timestamptz` | maintained by trigger |

Roles for this scope:

- `owner`: all CMS, SEO, media, user-role, and revision actions.
- `editor`: content, blog, Lost & Found, media, and SEO actions.
- `reception`: reserved for a later product; it receives no booking dashboard in this scope.

Implementation details:

1. Add rows only for selected existing Supabase Auth accounts.
2. Enable RLS with no browser-write policy; server service role bypasses RLS.
3. Do not use `user_metadata.role`; browser-accessible user metadata is not a secure authorization source.
4. Add `requireAdmin()` in source. It verifies the session, reads this table, and enforces role permissions.

### 2. `WebbookingContentRevisions`

Purpose: restore a previous CMS payload after an accidental edit.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` primary key | generated by database |
| `content_key` | `text` | e.g. `homepage_content`, `footer_content` |
| `payload` | `jsonb` | snapshot before update |
| `changed_by` | `uuid` nullable | FK to `auth.users(id)` |
| `created_at` | `timestamptz` | defaults to `now()` |

Implementation details:

1. Keep `SystemConfigs` and `WebBookingContent` unchanged.
2. Before an admin write, the server inserts the current value into this table.
3. Only `owner` can browse and restore revisions.
4. Add index `(content_key, created_at desc)`.

### 3. `WebbookingBlogPosts`

Purpose: daily articles with all five locales, media, scheduling, and SEO.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` primary key | generated by database |
| `slug` | `text` unique | stable public identifier |
| `title` | `jsonb` | `vi`, `en`, `cn`, `jp`, `kr` |
| `excerpt` | `jsonb` | same locale structure |
| `content` | `jsonb` | same locale structure |
| `category_i18n` | `jsonb` | localized category |
| `read_time_i18n` | `jsonb` | localized reading time |
| `cover_image` | `text` nullable | image/video URL |
| `cover_type` | `text` | `image` or `video` |
| `cover_alt` | `jsonb` | localized alt text |
| `status` | `text` | `draft`, `scheduled`, `published` |
| `published_at` | `timestamptz` nullable | public visibility timestamp |
| `author` | `text` nullable | optional byline |
| `seo_metadata` | `jsonb` | canonical, title, description, etc. |
| `created_at` | `timestamptz` | defaults to `now()` |
| `updated_at` | `timestamptz` | maintained by trigger |

Migration approach:

1. Create `WebbookingBlogPosts`; do not rename `blog_posts`.
2. If `blog_posts` exists, copy compatible rows into `WebbookingBlogPosts` with `ON CONFLICT (slug) DO NOTHING`.
3. Deploy source that reads `WebbookingBlogPosts` only after the copy is verified.
4. Retain `blog_posts` for one release as a rollback source; do not drop it during this project.
5. Use a public query where `(status IN ('published', 'scheduled')) AND published_at <= now()`.
   A cron that changes status is unnecessary for public visibility.

Recommended indexes:

- `(published_at desc)` partial index for `status IN ('published', 'scheduled')`.
- `slug` unique index.
- Optional GIN index on `title` only if search is introduced later.

### 4. `WebbookingLostFound`

Purpose: one row per found item, including its single active guest contact record.
This is intentionally a compact design for the current Lost & Found workflow.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` primary key | generated by database |
| `title` | `jsonb` | five locales |
| `detail` | `jsonb` | five locales |
| `found_at` | `jsonb` | five locales |
| `found_on` | `date` | date found |
| `image_url` | `text` nullable | public presentation image |
| `status` | `text` | `available`, `contacting`, `returned` |
| `sort_order` | `integer` | default `0` |
| `claimant_name` | `text` nullable | required once a claim exists |
| `claimant_phone` | `text` nullable | phone or email required once claimed |
| `claimant_email` | `text` nullable | phone or email required once claimed |
| `claim_note` | `text` nullable | identifying detail from guest |
| `claim_locale` | `text` nullable | `vi`, `en`, `cn`, `jp`, `kr` |
| `claim_status` | `text` | `none`, `new`, `contacted`, `resolved`, `archived` |
| `claim_created_at` | `timestamptz` nullable | first claim time |
| `claim_updated_at` | `timestamptz` nullable | latest claim update |
| `created_at` | `timestamptz` | defaults to `now()` |
| `updated_at` | `timestamptz` | maintained by trigger |

Constraints and indexes:

- Default `claim_status` is `none`.
- When `claim_status != 'none'`, require `claimant_name`, `claim_note`, and at least one of `claimant_phone` or `claimant_email`.
- Index `(status, claim_status, found_on desc)` for admin triage.
- RLS has no direct public `SELECT` for claim fields; public users submit through a server endpoint only.

Migration approach:

1. Keep the current `SystemConfigs.system_settings.lost_and_found.items` value intact.
2. Seed the current sample/default items into this new table with `claim_status = 'none'`.
3. Public source reads table rows first and falls back to the old JSON when zero rows exist.
4. After the admin and public pages pass production smoke tests, stop writing the old JSON.
5. One row has one active claim. If multiple claims per item become a real business requirement, add a separate `WebbookingLostFoundClaims` table in a later migration instead of overwriting contact history.

## Source Changes

### Authentication and Authorization

Create:

- `src/lib/api/requireAdmin.ts`
- `src/app/api/public/site-content/route.ts`

Change:

1. `src/middleware.ts` redirects unauthenticated `/admin/*` visitors to `/admin/login`.
2. `src/lib/api/withAuth.ts` removes its test bypass and calls `requireAdmin()`.
3. Every `/api/admin/*` route requires an active `WebbookingAdminUsers` role.
4. Hide `Quan ly Dat Lich` and `Tra Cuu Khach Hang` from `src/app/admin/layout.tsx`.
5. Return `403` for `/api/admin/bookings*`, or remove those routes only after confirming no internal client depends on them.

### Public Content Boundary

`/api/public/site-content` returns only allowlisted public data:

- footer and contact details
- homepage content and media
- history content
- Space, Design Journey, and Pure Relaxation media
- Blog editorial configuration
- public Lost & Found items

Move public components away from admin endpoints:

- `src/components/Footer/Footer.tsx`
- `src/components/Space/SpacePage.tsx`
- `src/components/DesignYourJourney/DesignYourJourneyPage.tsx`
- `src/components/PureRelaxation/PureRelaxationPage.tsx`

Only after those components use the new public endpoint may `/api/admin/content` and
`/api/admin/system-settings` be protected.

### Blog

- Change `PostsService` and public posts API to use `WebbookingBlogPosts`.
- Update admin post form with five tabs for title, excerpt, body, category, read time, and media alt text.
- Validate JSON locale objects, slug format, media URL, status, and publish date on the server.
- Keep content plain text with line breaks unless a sanitized rich-text format is added. Do not claim HTML support when output is plain text.

### Lost and Found

Create routes:

- `GET /api/public/lost-and-found`
- `POST /api/lost-and-found/claims`
- `GET|POST /api/admin/lost-and-found`
- `PUT|DELETE /api/admin/lost-and-found/[id]`

The public form validates `phone || email`, updates the single active claim server-side,
and returns a localized confirmation. The admin page manages item and claim statuses in
the same record.

## Storage and Secret Changes

### Existing buckets

Keep `media-uploads` to preserve all existing public URLs.

1. Route admin uploads through `/api/admin/media` using server credentials.
2. Validate MIME type, extension, size, and allowed folder server-side.
3. Retain public storage `SELECT` for website media.
4. Remove public storage `INSERT`, `UPDATE`, and `DELETE` policies only after all browser uploads use the server endpoint.
5. Move recruitment uploads behind a server upload endpoint; applicant images and certificates should not remain publicly writable.

### Credentials

1. Rotate SMTP credentials immediately.
2. Rotate Google Places API key immediately.
3. Remove hard-coded secret fallbacks from source.
4. Delete the production email diagnostics route or restrict it to `owner` and non-production environments.
5. Store all credentials in Vercel Environment Variables only.

### Chatbot

Use Vercel Firewall or Upstash rate limiting rather than a database table:

- 20 requests per IP per 10 minutes.
- message maximum: 1,000 characters.
- history maximum: 12 messages.
- do not expose provider error details to the client.

## Migration and Deployment Order

1. Export database schema, RLS policies, storage policies, functions, and data backups.
2. Rotate SMTP and Google credentials in their providers and Vercel.
3. Apply migration `202609XX_webbooking_admin_users.sql`; seed owner accounts.
4. Deploy public content endpoint and server upload proxies.
5. Verify all public pages still render current content.
6. Enable middleware and API authorization; protect every admin endpoint.
7. Apply `202609XX_webbooking_content_revisions.sql`.
8. Apply `202609XX_webbooking_blog_posts.sql`; copy legacy `blog_posts` data if present.
9. Deploy multilingual blog source and verify scheduled/public behavior.
10. Apply `202609XX_webbooking_lost_found.sql` for `WebbookingLostFound`.
11. Deploy public Lost & Found claim flow and protected admin management.
12. Remove public storage write policies after upload regression tests pass.

## Verification Checklist

### Authorization

- Guest receives `401` or `403` from every `/api/admin/*` endpoint.
- Owner and editor have only their intended CMS permissions.
- Public visitors still receive footer, history, service content, and media.

### CMS

- Saving a CMS block creates a `WebbookingContentRevisions` snapshot.
- A revision can restore a previous payload without losing unrelated config keys.
- Invalid JSON/content payload returns a validation error without updating config.

### Blog

- Draft is never public.
- Scheduled post appears after `published_at` without a manual status update.
- All five locales have safe fallback order: selected locale, English, Vietnamese.
- Image and video cover render correctly; alt text follows locale.

### Lost and Found

- Available and contacting items appear publicly; returned items follow the approved display rule.
- Claim submission requires name, identifying note, and phone or email.
- Claim contact fields are not publicly readable.
- Admin can update item and claim status in the same record.

### Storage and Security

- Anonymous user cannot upload, replace, or delete `media-uploads` objects.
- Existing public image/video URLs still load.
- Recruitment uploads are validated and cannot be read or modified without the intended permission.
- SMTP, Google, and Gemini secrets are absent from committed source.

## Required Production Schema Audit

Run this audit before writing final migrations:

```sql
select table_name, column_name, data_type, is_nullable
from information_schema.columns
where table_schema = 'public'
  and table_name in (
    'Bookings', 'BookingItems', 'Customers', 'Services', 'SystemConfigs',
    'WebBookingContent', 'MarketingMedia', 'blog_posts', 'flipbook_pages'
  )
order by table_name, ordinal_position;

select schemaname, tablename, policyname, roles, cmd, qual, with_check
from pg_policies
where schemaname in ('public', 'storage')
order by schemaname, tablename, policyname;

select routine_schema, routine_name, data_type
from information_schema.routines
where routine_schema = 'public'
order by routine_name;
```

Do not apply final SQL until this output has been reviewed against the plan.
